# 0.5：等比贴图、关节锚点、地图镜头与连续蹬墙

## 0.5.1 修正：跑动与蹬墙输入

跑动不再对每段手臂、腿部独立叠加「素材站姿角度减原版站姿角度」。两套站姿左右不对称，旧映射会让其中一侧膝盖、手肘反折。跑动现使用原版跑步循环的肢体方向，结合用户校准的长度、锚点、连接偏移和旋转；鞋子保持已校准的落脚角度。头、身体和其他动作沿用原有处理；死亡打断跑动时也不会误用这次新增的跑步映射。

蹬墙增加 120 毫秒跳跃按键缓存和 100 毫秒离墙宽限，均按物理时间计算。提前按下可在首次实际碰墙的那个物理帧立即执行；稍晚按下可使用尚未消耗的最近墙面接触。上一次跳跃的延长状态不再阻止新一次蹬墙。成功跳跃会消费请求和宽限，按住不自动连跳，也不能消费同一次接触在空中二连跳。原有跳跃冲量、水平最大移速、加速度和下降滑墙阻力保持原值。

输入格式更新为 3，新增 `JUMP_PRESS = 32`，记录实际按下边沿。即使按下和松开都发生在相邻物理更新之间，下一帧也能收到一次请求；`JUMP = 4` 仍表示按住，用于高度控制。模拟版本为 `n14-port-0.5.1`。重试、失焦释放输入及暂停恢复不会遗留待执行的跳跃。

检查结果：`logs/v051-tests.json` 共 7234 项通过，覆盖完整 720 个采样间隔的跑步循环、循环接缝、关节连接及弯曲方向，以及提前按、碰墙当帧按、离墙宽限、过期请求、长按和重置。提前点按的双墙夹道测试连续蹬墙 16 次，峰值上升速度约 525.6 像素/秒。原有模拟、UI、按键、贴图、无人机、布娃娃及镜头回归通过。真实 Windows 窗口检查 14 项通过，包括默认/改绑跳跃键在两次物理更新之间完整点按、暂停恢复，以及原有全屏与窗口尺寸检查。跑步画面见 `logs/v051-run.png`，36 帧连续预览保存在 `logs/v051-run/`。

## 操作

首页 → 自定义贴图 → 角色部位 → 选中已导入图片的部位 → **关节与比例…**。

- 拖动蓝点设置近端关节，拖动橙点设置远端关节。锚点按裁剪后的可见图像归一化：左上是 `(0, 0)`，右下是 `(1, 1)`，也允许在图像边界外设置连接点。
- “图像宽度”只做等比缩放；“整体等比尺寸”一起缩放完整角色。“连接偏移”沿父骨骼的局部坐标移动连接点，“角度偏移”修正图片方向。调整实时预览并自动保存，可撤销本次打开编辑器之后的修改。
- 短腿、长腿及较大的头部不再被拉伸到 N 的固定骨长。骨骼长度由图片尺寸和两个锚点之间的距离确定，下一级部件接到上一级的远端关节。原图纵横比保持不变，角色模型可以超出原有碰撞圆。
- 碰撞箱仍按设置显示。贴图布局数据放在 `build/userdata/skins/layout.json`，与 `skins.json` 中的图片清单分开保存。角色外观不会改变移动和碰撞规则。
- 场景实体预览直接使用 `world_view.gd` 的实际绘制逻辑；守卫、冲撞方块、弹性方块等默认图形均可预览。预览碰撞线绘制在贴图上层。

“应用两个测试用例”会安装校准后的能天使与源石虫。若旧版本保存的 12 个部位全部仍为内置能天使图片、且没有布局文件，会自动采用新校准；用户导入的其他图像不被覆盖。

## 能天使校准依据

使用 [PRTS 能天使原始骨骼资源](https://prts.wiki/w/%E8%83%BD%E5%A4%A9%E4%BD%BF/spine) 的设置姿态，原始文件在 `sources/prts/exusiai/`。不是按新贴图的外接矩形猜测关节中心：`prepare_demo_skins.gd` 将原骨骼起点、末端和父子连接位置映射到每个导出 PNG 的裁剪坐标中，同时保留源部件的相对比例。

校准包括肩部/髋部的左右连接偏移、肘/膝/踝的共享端点、头部颈根锚点与前后遮挡层。原始图像单位按统一比例换算为游戏显示单位。跑动采用原 N 轨迹角度的变化量，默认摆幅为 0.65；空中和贴墙使用相应动作的方向角，重新计算适合新骨长的关节位置。这是按原始骨骼比例做的动作适配，并非直接播放《明日方舟》的完整 Spine 动画。

效果见 [0.5 动作对照](../logs/v05-presentation.png) 与 [关节编辑器](../logs/v05-rig-editor.png)。

## 地图渲染接口

游戏上方“地图”数值可调 **1–4 倍**，默认 **1.5 倍跟随角色**；“全图”回到 1 倍，“跟随”恢复角色跟随。缩放值自动保存。地图使用独立的 `SubViewport`，实际只显示对应世界区域；HUD、暂停、设置和死亡提示保留原尺寸。

`NinjaMapView` 持有独立的 `NinjaMapCamera`，位置均为地图世界坐标。现有地图为 792×600。以下接口可在游戏运行中调用，不需要重新加载关卡：

```gdscript
# 默认单人跟随；snap 可立即切换，省略时平滑过渡。
main.map_view.set_view_policy({"mode": "follow", "zoom": 2.0, "snap": true})

# 固定取景中心。
main.map_view.set_view_policy({"mode": "fixed", "center": Vector2(400, 300), "zoom": 3.0})

# 多目标取景：每帧更新目标位置；自动扩大视野以包含全部目标。
# zoom 在 group 模式中为放大上限；目标远离时会及时缩小。
main.map_view.set_targets([player_one.pos, player_two.pos])
main.map_view.set_view_policy({"mode": "group", "zoom": 3.0})

# 自定义策略；回调收到 player、targets、delta 和 map_size。
main.map_view.set_view_policy({"mode": "custom"}, func(context: Dictionary) -> Dictionary:
    return {"center": context.player + Vector2(50, 0), "zoom": 2.0})

# 当前实际渲染区域和恢复默认策略。
var area: Rect2 = main.map_view.visible_rect
main.map_view.reset_follow()
```

取景范围始终限制在地图边界内。镜头配置只作用于画布变换，不写入模拟状态；只渲染区域内画面，整张地图的物理和实体 AI 仍继续运行。多目标接口已实现，但本版本仍只有单人玩法，不包含联网或第二名玩家控制逻辑。

## 连续蹬墙

对照本地原版 AVM1 的 `SetupParams`、`Think`、`Jump` 与 `HandleCollisions`。符号化检查保存在 `logs/v05-reference-think.txt` 和 `logs/v05-reference-collision.txt`。

原版 `maxspeedAir`/`maxspeedGround` 限制的是按键水平加速。`Jump` 在同方向现有速度上叠加冲量，只清除反方向分量。因此向上移动时再蹬墙，上升速度可以累加，不能用水平跑速上限截断。原版 `terminal_vel` 在落地伤害判断中使用，也不是上升速度硬上限。

0.4 为增强墙面阻力，额外在初次碰墙及持续顶墙时削减了上升切向速度。0.5 将这项增强阻力限定为向下滑墙阶段，让新墙面的上升接触保留动量；松开再按跳跃会继续叠加原有蹬墙冲量。下降时的较强滑墙阻力保留，这是此前按试玩反馈指定的改动。模拟仍为 120 Hz，没有切回原版模拟步长。

狭窄双墙测试通过实际地形接触连续蹬墙，前几次起跳上升速度约为 **180.7、245.5、308.6、370.0 像素/秒**，已超过当前 216 的水平跑速。测试中的极窄通道允许继续快速累积；这不是设置里“最大移速”控制的常规水平跑速。
